# Unify auth/users credential boundary (login management)

- [ ] Eliminate raw `SystemUser` (with password hash) crossing auth/users boundary
  - **Context:** Bug in `system:auth:session:create` (`CreateSession` in `core/system/auth/service.go:97`): login response leaked password hash. `AuthService` calls `s.users.GetByEmail` (returns full `SystemUser` with `Password` hash, see `core/system/users/model/system_user_methods.go:55`), then manually sanitizes via `common.ContextWithSanitizationScope(ctx, "users")` (`core/system/auth/service.go:116`) into untyped `map[string]any` (`LoginDocumentView.User` in `core/system/auth/model/outputs.go:19`). Previous code used scope `"_user_"` (collection name) which has no registered rules, so it fell back to global `MaskPreserve` and leaked. Fix was one-line scope change, but root cause remains.
  - **Architectural issue:** Two parallel redaction mechanisms with no owned contract: (1) static type-safe `SystemUser.Public() -> UserPublic` (no `Password` field, `core/system/users/model/system_user_methods.go:215`, `users.schema.model.go:124`) used by `UsersService` everywhere (`core/system/users/service.go:40`), bypassed by `auth`; (2) dynamic stringly-typed `Sanitize(ctx+scope)` with per-feature `SanitizationRules()` scoped by message name (`core/runtime/sanitization-dispatcher.go:82`, `core/system/module.go:84`). Cross-feature read (`auth` message, `users` data) can never satisfy producer-keyed scope: `auth` rules (`core/system/auth/sanitization.go:5`) are empty, `users` rules (`core/system/users/sanitization.go:9`) hold `password: MaskRedact`. Compiler cannot help because wire type is `map[string]any`.
  - **Details:** Single ownership of credential lifecycle. Preferred (minimal, no route churn): keep `system:auth:*` / `system:users:*` message names, but make `users` own the hash. Add `SystemUsers.Authenticate(ctx, email, password) (*UserPublic, error)` (or `VerifyCredentials -> UserPublic`) that does `GetByEmail` + `runtime.CheckPassword` internally and never returns the hash. `AuthService.CreateSession` and `ElevateToken` call it instead of `GetByEmail` + `CheckPassword`. Change `LoginDocumentView.User` from `map[string]any` to typed `*usersmodel.UserPublic` (or local view embedding it) so `password` cannot compile back in. Remove manual `Sanitize(sctx)` call in `CreateSession` — `UserPublic` needs no redaction; dispatcher `auth`-scope sanitize becomes a no-op safety net.
  - **Alternative (larger):** Merge `auth` + `users` into one identity/login domain as hinted (shared model, shared sanitization scope, one `SanitizationRules`). Only do this if route rename (`system:login:*`) is acceptable; otherwise prefer the `Authenticate()` ownership fix above.
  - **Files:** Modify `core/system/users/model/system_user_methods.go` (add `Authenticate`), `core/system/auth/service.go:97-132,350-378` (use it), `core/system/auth/model/outputs.go:14-25` (type `User`), `core/system/auth/registrations.go:33` (output schema regen if type changes). Audit remaining raw uses: `GetPasswordHash`, `GetByEmail` callers via `grep GetByEmail|SystemUser{Password`.
  - **Acceptance:** `grep -rn "MustDocument().Sanitize" core/system/auth` empty; `LoginDocumentView.User` is typed, not `map[string]any`; no `auth` import path constructs a `SystemUser` with `Password` except inside `users/model`.

- [ ] Add regression test: login response never contains password/hash

Also assert `ElevateToken` path does not return user hash. Test must fail if `CreateSession` reverts to returning raw `SystemUser` map or wrong sanitize scope.

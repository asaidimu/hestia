# Sanitization regression follow-ups

- [ ] Surface document sanitization failures instead of silently dropping rows
  - **Context:** The `notes` collection bug (2026-08-22): query responses returned `data: []` while pagination reported `count: N`. Root cause chain: global sanitize pattern `(?i)auth` matched the `authors` array field → masked values are always strings → container write into an array slot failed → `Document.Sanitize()` errored → `serializeOutputField` in `core/interface/http/register.go` dropped every errored document via `if sane, _ := d.Sanitize(); sane != nil`.
  - **Done:** `sanitizeConfig()` in `core/internal/boot/persistence.go` is now preserve-only globally with targeted, collection-scoped rules (exact field names only). Library-level gap documented as devnote `#sanitize-type-blindness` in go-anansi `core/sanitize/sanitizer.go`.
  - **Remaining:** `register.go` swallows the `Sanitize()` error (`sane, _`). At minimum log it; better, fail the request or return a partial-result warning so type/policy mismatches are observable instead of manifesting as mysteriously empty pages.
- [ ] Make go-anansi sanitizer type-aware (upstream)
  - **Context:** `applyPolicy` stringifies every value (`fmt.Sprintf %v`) regardless of declared field type; arrays of strings could be masked element-wise instead of failing. Tracked as devnote `#sanitize-type-blindness` in `~/projects/go-anansi/core/sanitize/sanitizer.go`. Decision for now: no library change shipped; app configs must keep masking rules targeted so patterns only ever hit string fields.
- [*] Bump go-anansi to the release carrying #tx-watcher-goroutine-leak
  - **Context:** Every top-level write leaked one goroutine: `NativeInteractor.StartTransaction` spawned a ctx-cancellation watcher even for contexts without a Done channel (context.Background(), fasthttp request contexts), parking it forever on a nil-channel receive. Reproduced via in-process dispatch harness (200 writes → 200 parked goroutines); fixed in go-anansi with a `ctx.Done() != nil` guard + regression tests (`core/query/native/interactor_test.go`). Verified through hestia via temporary replace: goroutines flat across 200 creates/settings writes.
  - **Done:** Fix + tests + devnote live in ~/projects/go-anansi (unreleased). hestia's pinned v8.5.9 still has the leak.
  - **Done (2026-08-23):** go-anansi v8.5.11 released; hestia pinned to it; regression test unskipped and green.
- [X] go-anansi v8.5.11 — encoder array<object> recursion
  - **Context:** POST /system/notifications/notification/create with a populated `actions` array OOM-killed the server: pool.FromJSON's metadata checksum finalization ran the container→JSON encoder, whose writeChildren resolved array-element entry names through the root address reverse-map — full paths like "payload.actions.label" never matched the element prefix "actions", so emitObject recursed forever on joinPrefix(prefix,"payload"), allocating per level.
  - **Fix:** writeChildren now emits elements via writeObjectAt, resolving names slot-locally by descriptor-word comparison (allocation-free). Shipped in go-anansi v8.5.11 (`fix(encoding): prevent infinite recursion in JSON array object encoding`); regression tests in go-anansi notif_matrix_test.go. Known limitation noted in devnote #encoder-array-object-recursion: object-typed members inside array children emit flattened rather than nested.
